# 开发踩坑复盘

本文记录项目从 2026 年 7 月 19 日到 7 月 26 日开发过程中实际遇到的问题、原因和处理方式，供项目答辩与后续维护参考。

## HarmonyOS 与 ArkTS

### 1. ArkTS 严格类型检查比 TypeScript 更严格

- **现象**：无类型对象字面量、联合类型、索引访问、回调参数或路由参数在 ArkTSCheck 阶段报错。
- **原因**：ArkTS API 24 对静态类型、可空值和跨页面参数有更严格的约束。
- **处理**：为网络响应、卡片数据、路由参数和回调声明明确接口；仅在路由边界进行类型转换，避免在业务页面传播动态类型。
- **经验**：新增页面时先确定数据模型，再写 UI，可以显著减少后期类型修补。

### 2. 中文输入法组合态被受控输入框打断

- **现象**：AI 输入框输入拼音时，候选中文尚未确认，页面状态更新就把预编辑文本覆盖，表现为无法正常输入中文。
- **原因**：输入法组合期间把预编辑值立即回写到受控状态，触发组件重新渲染。
- **处理**：组合态期间保留输入框内部值，待输入法确认文本后再同步业务状态；发送和清空操作仍由统一状态控制。
- **经验**：输入框不能只用英文键盘测试，必须覆盖中文拼音、候选确认、删除和连续输入。

### 3. Navigation 只能保留一个根导航容器

- **现象**：子页面重复出现底部导航或返回栈异常。
- **原因**：多个页面分别创建根 `Navigation`，破坏统一的 `NavPathStack`。
- **处理**：应用只保留一个根导航；四个主入口复用主 Tab，详情页使用 `NavDestination`。

### 4. 消息操作必须绑定具体 AI 消息

- **现象**：点击历史消息的复制或语音播报，可能读取最新一条回复；多次进入页面后回调重复执行。
- **原因**：复制、TTS 和卡片状态放在页面级全局变量中，或页面退出时没有解除监听。
- **处理**：回调携带消息 ID，并从消息模型读取对应文本；页面销毁时释放录音、播报和订阅资源。

### 5. 构建成功不等于设备能力可用

- **现象**：SDK 中存在 CoreSpeechKit、CoreVisionKit 或分布式类型，模拟器却无法执行对应功能。
- **原因**：API 类型可编译只代表 SDK 支持，实际能力还依赖设备型号、系统版本、权限和签名。
- **处理**：运行时进行能力检测，失败时显示明确提示并降级；最终结论以目标真机验收为准。

## 网络与后端联调

### 1. 设备中的 127.0.0.1 不是开发电脑

- **现象**：电脑浏览器能访问 FastAPI，HarmonyOS 模拟器或真机请求超时。
- **原因**：设备内的 `127.0.0.1` 指向设备自身。
- **处理**：FastAPI 监听 `0.0.0.0`，客户端 `API_BASE_URL` 使用电脑当前局域网 IPv4，并确认防火墙允许 8000 端口。
- **经验**：切换 Wi-Fi、热点或 DHCP 地址变化后，需要更新客户端地址并重新构建。

### 2. Windows 端口 8000 被重复占用

- **现象**：Uvicorn 报 `[WinError 10048]`，随后应用关闭。
- **原因**：已有后端进程占用了 `0.0.0.0:8000`，又启动了第二个实例。
- **处理**：先通过 `Get-NetTCPConnection -LocalPort 8000` 和进程 ID 确认已有服务；若已有服务正确则直接复用，否则只终止明确的旧进程后再启动。
- **经验**：日志中的 `Application startup complete` 不代表绑定最终成功，还要确认没有紧随其后的端口错误。

### 3. 代码中存在接口文件不等于接口已经启用

- **现象**：前端调用持续返回 404，但仓库内能找到对应 API 文件。
- **原因**：路由没有被聚合到 `api_router`，或 Uvicorn 从错误目录加载了旧应用。
- **处理**：同时检查路由注册、`server.main:app`、OpenAPI 文档和当前监听进程，不只检查文件是否存在。

### 4. 后端不可用时不能伪装成功

- **处理原则**：展示型首页可以使用明确标识的本地兜底数据；AI 对话、任务提交和数据库写入必须提示失败并保留重试入口，不能把 Mock 结果冒充真实业务结果。

## AI、SSE 与学习计划

### 1. SSE 重试必须保持请求幂等

- **现象**：流式连接失败后再次发送，可能重复生成卡片或写入业务数据。
- **原因**：降级请求使用了新的 `clientMessageId`。
- **处理**：SSE 与普通请求复用同一消息 ID；收到部分 `delta` 后若连接中断，保留已有内容并由用户主动重试。

### 2. AI 卡片状态不能使用页面级全局变量

- **现象**：历史回答显示了其他消息的卡片、来源或错误状态。
- **处理**：`cards`、`sources`、错误、降级标志和流式状态都绑定到具体 AI 消息。

### 3. 六年级档案因目录精确匹配为空导致计划生成失败

- **现象**：学生已有成绩和薄弱点，但生成学习计划总是返回失败。
- **原因**：旧逻辑要求学生年级、学科与课程或试卷目录精确匹配；现有目录只有五年级数学，六年级匹配为空后抛出 404。
- **处理**：学习计划改为使用最新学科档案、成绩层次、薄弱知识点和每周学习时长，确定性生成 7 天预览，不再依赖目录是否齐全。
- **边界**：预览返回 `planId: 0` 和合成任务 ID，不写入 `study_tasks`；“添加到我的学习计划”目前是演示按钮。

### 4. 模型输出必须经过结构校验

- **现象**：AI 组卷偶尔返回缺字段、非 JSON 文本或题目数量不正确。
- **处理**：提示词约束 JSON 结构，后端再校验题型、选项、答案、分值和总题数；模型不可用或结果不合法时走可解释降级。
- **经验**：大模型负责理解与表达，业务 ID、成绩、价格、任务状态和统计数据必须来自工具与数据库。

## 语音能力

### 1. 录音格式与识别引擎不一致

- **现象**：设备能录音，但后端识别为空或直接报格式错误。
- **原因**：设备输出格式与 Vosk 所需的 PCM/WAV 参数不同。
- **处理**：后端先通过 FFmpeg 统一转换，再调用 Vosk；缺少本地模型时按配置尝试备用识别服务，并返回可理解的错误信息。

### 2. 音频转换和识别不能阻塞异步接口

- **原因**：FFmpeg 和离线识别属于阻塞、CPU 或进程密集操作，直接在 FastAPI 异步路由中执行会拖慢其他请求。
- **处理**：API 层只负责参数和响应，语音业务下沉到服务层，阻塞步骤放在线程池执行。

### 3. 模拟器不能代替真机语音验收

- **处理**：代码和 HAP 构建用于证明接口完整；麦克风授权、录音、系统播报和噪声环境识别仍标注为待真机验证。

## 数据库与安全

### 1. 自动补丁必须允许重复执行

- **现象**：启动日志出现 `Duplicate key name 'ix_papers_created_by'`。
- **原因**：索引已经存在，兼容补丁再次尝试创建。
- **处理**：补丁服务将“索引已存在”识别为已应用状态，不中断启动；长期结构仍应由 Alembic 迁移统一管理。

### 2. `create_all()` 不能替代完整迁移

- **问题**：热重载时可以创建新表，但 Alembic 版本和真实结构可能处于半迁移状态。
- **处理**：正式结构变化使用迁移；兼容补丁保持幂等，不能通过删除开发数据库掩盖问题。

### 3. 测试数据库必须与开发 MySQL 隔离

- **风险**：测试夹具包含建表和清理动作，配置错误会破坏开发数据。
- **处理**：在导入应用模块前切换到隔离 SQLite 和 Mock AI Provider，禁止测试对开发 MySQL 执行清理。

### 4. 密钥只允许进入环境变量

- **规则**：DeepSeek Key、JWT Secret 和数据库密码只写入 `.env` 或系统环境变量，不进入日志、截图、提示词档案和 Git 提交；已经暴露的密钥必须撤销。

## HarmonyOS 原生分布式能力

### 1. 普通云端同步不等于原生分布式

- **结论**：本项目的分布式代码证据是 `distributedDataObject`、`DISTRIBUTED_DATASYNC` 和 `UIAbility.onContinue`，FastAPI 与 MySQL 仍负责真实业务数据。

### 2. 分布式会话必须按账号隔离

- **处理**：同一账号使用稳定会话 ID `smartstudy_user_<userId>`；登录恢复完成后才消费接续状态，退出登录、切换账号或关闭功能时解除监听并离开会话。

### 3. 分布式对象只传递最小上下文

- **白名单**：版本、页面、任务 ID、任务状态、选中日期、筛选条件和更新时间。
- **禁止同步**：JWT、用户名、成绩、答案、AI 对话和数据库凭据。
- **一致性**：任务先保存到后端，再发布跨设备变化；接收设备重新请求 FastAPI，MySQL 始终是最终事实来源。

### 4. 相同签名和可信设备是硬条件

- **现象**：单模拟器构建通过，却无法展示双设备接续。
- **原因**：原生分布式需要两台支持该能力的可信设备、相同应用签名和系统分布式环境。
- **结论**：当前 unsigned HAP 只能证明编译通过，不能写成“双真机已经验证”。完整步骤见 [分布式部署与验收说明](DISTRIBUTED_DEPLOYMENT.md)。

## 代码分层与注释规范

- 页面负责交互和状态展示，API 层负责协议转换，Service 层承载业务规则，AI Tool 负责只读查询或受控业务调用，数据库模型负责持久化。
- 注释优先解释约束、降级原因、安全边界和非直观业务选择，不重复翻译函数名或逐行描述代码。
- 删除失效的 AI 说明、被替代的卡片组件和误导性 Mock 注释；保留仍能帮助维护者理解设计取舍的自定义注释。
- 材料中的“已实现”“已构建”“已测试”和“待真机验收”必须分别表述，不能用构建成功替代运行效果。
