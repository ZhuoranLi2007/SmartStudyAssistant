# 代码分层与注释约定

## HarmonyOS 客户端

```text
pages / components
        ↓
viewModel（跨组件状态和交互编排）
        ↓
service（HTTP、会话、设备与分布式能力）
        ↓
model / common（类型、路由和配置）
```

- 页面负责展示、用户操作和页面生命周期，不直接拼接后端业务数据。
- Service 统一处理网络、认证、语音、分布式会话和数据转换。
- Model 使用明确的 ArkTS 类型，页面之间只传递白名单路由参数。

## FastAPI 后端

```text
api（协议与状态码）
        ↓
services（业务规则与事务数据）
        ↑
tools / ai（Agent 编排与受控工具调用）
        ↓
models / database（实体与持久化）
```

- API Router 只处理请求解析、依赖注入、错误映射和响应封装。
- Service 承担课程、试卷、学习、语音和数据库兼容等业务逻辑。
- AI Agent 不直接操作数据库，只能通过白名单 Tool 调用 Service。
- MySQL 是业务事实来源，分布式对象和大模型输出不能覆盖服务端校验结果。

## 注释原则

- 注释解释“为什么这样做”、业务口径、安全边界和兼容原因。
- 不重复翻译函数名、条件判断或下一行代码。
- 不保留模板生成说明、编号式操作说明和已经失效的历史描述。
- 变更业务规则时同步修改相关注释和测试，避免注释与代码含义分离。
